# 10. 산출물 양식

`AnalysisRun` 결과로 만드는 3개 산출물의 양식. 화면 미리보기, Excel, Markdown 보고서가
모두 이 정의를 따른다.

---

## 1. Compliance Matrix (기술규격 대응표) — FR-18

공고문 제출서류 6번 `기술규격 대응표 / 비고: 항목별 근거 명시` 에 대응하는 문서다.
공고문 5.2 `규격에 미달하는 항목이 있는 경우 그 사유와 대체방안을 대응표에 기재하여야 한다`
에 따라 **사유**와 **대체방안** 열이 필수다.

### 1.1 열 정의

| # | 열 | 원천 | 비고 |
|---|---|---|---|
| 1 | 조항 | `Requirement.clause_no` | 등폭 글꼴, 숫자 튜플 정렬 |
| 2 | 구분 | `Requirement.chapter` | 예: `제3장 구조 요구사항` |
| 3 | 분류 | `Requirement.category` 라벨 | 예: `등급` |
| 4 | 항목 | `Requirement.item` | |
| 5 | 요구조건 | `Requirement.requirement_text` | 원문 표기 유지 |
| 6 | 자사 사양 | `Assessment.our_value` | 없으면 `-` |
| 7 | 판정 | `Assessment.verdict` 라벨 | 충족 / 보완 필요 / 확인 필요 |
| 8 | 사유 | `gap_detail` 또는 `rationale` | `MEET` 은 `rationale` 요약 1문장 |
| 9 | 대체방안 | `remedy` + `side_effects` 문자열화 | `MEET` 은 빈칸 |
| 10 | 근거 문서 | `Evidence.doc_title` (1순위) | 예: `제품 카탈로그 (HB-CAT-2025-02)` |
| 11 | 근거 위치 | `Evidence.location` (+ `page_no`) | 예: `2.2 구조` |
| 12 | 비고 | 수정 여부, 교차조항 이슈 참조 | 예: `조항 3.2와 상충 (이슈 1)` |

`side_effects` 문자열화: `무게 +1.4kg, 납기 +3주` 형식. `field` 라벨 매핑은
`weight→무게`, `price→단가`, `lead_time→납기`, `temperature→온도`.

### 1.2 샘플 기준 기대 출력 (일부)

| 조항 | 분류 | 항목 | 요구조건 | 자사 사양 | 판정 | 사유 | 대체방안 | 근거 문서 | 근거 위치 |
|---|---|---|---|---|---|---|---|---|---|
| 2.1 | 효율 | 소비전력 | 150 W 이하 | 140 W | 충족 | 카탈로그 표기 140W로 요구 이내 | | 제품 카탈로그 (HB-CAT-2025-02) | 2.1 성능 |
| 3.1 | 등급 | 방수·방진 등급 | IP66 이상 | IP65 | 보완 필요 | 한 등급 미달 (IP65 < IP66) | IP66 강화 하우징 선택사양 적용 (무게 +1.4kg, 납기 +3주) | 제품 카탈로그 (HB-CAT-2025-02) | 2.2 구조 |
| 3.3 | 성능 | 동작 온도범위 | -20℃ ~ 50℃ | -20℃ ~ 45℃ | 보완 필요 | 상한 5℃ 부족 | 확장 온도 사양(-30~55℃) 적용 (단가 +12%, 납기 +2주) | 제품 카탈로그 (HB-CAT-2025-02) | 2.2 구조 / 2.3 선택사양 |
| 4.3 | 시험규격 | 내염수분무 시험 | 염해 환경 대응, 240시간 | - | 확인 필요 | 해당 성적서 없음. 설비 현황에 염수분무 시험기 미보유 명시 | 외부 공인기관 위탁시험 가능 여부 발주처 확인 필요 | 인증·시험·실적 현황 (HB-QA-2025-07) | 3. 시험 설비 보유 현황 |
| 5.4 | 실적 | 납품실적 | 최근 5년 발전소 납품실적 3건 이상 | 발전 부문 2건 | 보완 필요 | 발전 부문 2건 (남부발전 2022, 서부발전 2024). 산업·공공 부문은 요구 범위 제외 | - | 인증·시험·실적 현황 (HB-QA-2025-07) | 4.1 발전 부문 |

### 1.3 교차조항 이슈 표기

대응표 하단에 별도 블록으로 붙인다. 표 안에 숨기지 않는다.

```
※ 조항 간 상충 사항
[1] 조항 3.1, 3.2 — IP66 선택사양 적용 시 무게 제한 위반
    조항 3.1(IP66 이상)은 표준 사양 IP65로 미달하며 IP66 강화 하우징 선택사양으로
    충족할 수 있으나, 본체 무게가 7.2 + 1.4 = 8.6kg 가 되어 조항 3.2(8kg 이하)를
    위반합니다. 두 조항을 동시에 만족하는 구성이 없어 우선 적용 기준 확인이 필요합니다.
```

## 2. 입찰 체크리스트 — FR-19

### 2.1 제출서류 (공고문 제출서류 8건)

| # | 열 | 원천 |
|---|---|---|
| 1 | 연번 | `SubmissionItem.seq` |
| 2 | 서류명 | `name` |
| 3 | 공고 비고 | `note` |
| 4 | 자사 상태 | `status` 라벨 (보유 / 발급 필요 / 확인 필요) |
| 5 | 근거 | `evidence_text` |
| 6 | 확인 | 체크박스 (`is_checked`) |

샘플 기준 기대 출력:

| 연번 | 서류명 | 공고 비고 | 자사 상태 | 근거 |
|---|---|---|---|---|
| 1 | 입찰참가신청서 | 소정양식 | 발급 필요 | 발주처 양식 작성 |
| 2 | 사업자등록증 사본 | | 발급 필요 | |
| 3 | KS 인증서 사본 | | 보유 | 인증현황 1절 KS 인증 KSC-2022-1180 (유효 2027-03-14) |
| 4 | 고효율에너지기자재 인증서 사본 | | 보유 | 인증현황 1절 HE-2023-0471 (유효 2026-08-20) |
| 5 | 납품실적증명서 | 발주처 직인 날인본 | 확인 필요 | 발전 부문 2건. 요구 3건 미달 (조항 5.4 참조) |
| 6 | 기술규격 대응표 | 항목별 근거 명시 | 발급 필요 | 본 시스템 산출물로 제출 |
| 7 | 제품 카탈로그 | | 보유 | 제품 카탈로그 HB-CAT-2025-02 |
| 8 | 공인시험기관 시험성적서 | 기술사양서 제4장 전체 | 확인 필요 | 4.1·4.2 성적서 보유, 4.3·4.4 성적서 없음 |

8번 행은 `기술사양서 제4장 전체` 를 요구하므로 4.1~4.4 판정을 종합해 상태를 정한다.
하나라도 `CHECK` 면 `확인 필요` 다.

### 2.2 참가자격

| 연번 | 자격 요건 | 자사 상태 | 비고 |
|---|---|---|---|
| 3.1 | LED 조명 제조업 등록을 필한 자 | 확인 필요 | 자사 자료에 제조업 등록증 정보 없음 |
| 3.2 | KS 인증을 보유한 자 | 보유 | KSC-2022-1180 |
| 3.3 | 최근 5년 이내 발전소 납품실적이 3건 이상인 자 | 확인 필요 | 발전 부문 2건. 조항 5.4와 동일 사안 |

`3.1` 은 지식베이스에 근거가 없으므로 `확인 필요` 가 정답이다. 추측해서 `보유` 로
채우지 않는다 (원칙 3).

### 2.3 일정

| 구분 | 일시 | 남은 기간 |
|---|---|---|
| 기술질의 접수마감 | 2025-07-10 | D-n |
| 입찰서 제출마감 | 2025-07-24 10:00 | D-n |
| 개찰 | 2025-07-24 11:00 | |

기준일은 산출물 생성일. `D-n` 이 음수면 `마감` 으로 표기한다.
**기술질의 접수마감이 입찰서 제출마감보다 2주 앞선다** — 기술질의서를 먼저 내야 하므로
체크리스트 상단에 이 마감을 강조한다.

## 3. 기술질의서 초안 — FR-20

### 3.1 문서 머리

```
기술질의서

수신: 한국발전기술공사 자재구매처
참조: LED 투광등 150W급 구매 입찰 (공고번호 KPG-2025-EQ-0417)
      기술사양서 KPG-2025-TS-0417
발신: 한빛조명(주)
작성일: YYYY-MM-DD

아래 사항에 대하여 회신하여 주시기 바랍니다.
```

### 3.2 질의 항목 양식

```
[질의 n] 조항 {clause_refs 쉼표 구분} 관련
{body}
```

### 3.3 샘플 기준 기대 출력

```
[질의 1] 조항 4.3 관련
내염수분무 시험(염해 환경 대응, 240시간) 성적서를 외부 공인기관 위탁으로 대체
제출 가능한지 회신하여 주시기 바랍니다. 자사는 염수분무 시험 설비를 보유하지 않아
사내 시험 성적서를 제출할 수 없습니다.

[질의 2] 조항 4.4 관련
내진동 시험(KS C 7658) 성적서를 외부 공인기관 위탁으로 대체 제출 가능한지
회신하여 주시기 바랍니다.

[질의 3] 조항 3.1 및 3.2 관련
IP66 사양 적용 시 본체 무게가 8kg를 초과합니다(IP65 표준 7.2kg + 강화 하우징 1.4kg
= 8.6kg). 두 조항 중 우선 적용 기준을 회신하여 주시기 바랍니다.

[질의 4] 조항 3.3 관련
동작 온도범위 상한 요구(50℃)에 대해 자사 표준 사양은 45℃이며, 확장 온도 사양
(-30℃ ~ 55℃) 적용으로 충족 가능합니다. 해당 선택사양 적용을 승인하실 수 있는지
회신하여 주시기 바랍니다.

[질의 5] 조항 5.3 관련
보증기간 요구(납품 후 3년 이상)에 대해 자사 표준 보증은 2년입니다. 연장 보증 조건
협의가 가능한지 회신하여 주시기 바랍니다.

[질의 6] 조항 5.4 및 입찰공고 3.3 관련
최근 5년 발전소 납품실적 요구(3건 이상)에 대해 자사 발전 부문 실적은 2건
(한국남부발전 2022, 한국서부발전 2024)입니다. 산업·공공 부문 실적(7건)의 인정
가능 여부를 회신하여 주시기 바랍니다.
```

### 3.4 문안 규칙

- 한 질의 2~3문장. 조항번호를 반드시 앞에 명시한다.
- 정중한 공문체. `~하여 주시기 바랍니다` 로 끝낸다.
- 근거에 있는 수치만 인용한다.
- 미달 사실을 숨기지 않는다. 미달은 미달로 적고 대체방안을 제시한다.
- 같은 원인의 질의는 하나로 합친다 (3.1 + 3.2, 5.4 + 공고 3.3).
- 질의 순서: `CHECK` → 교차조항 이슈 → `GAP` 대체방안 승인 요청.
  확인이 꼭 필요한 것을 앞에 둔다.

### 3.5 문서 꼬리

```
회신 요청 기한: 2025-07-10 (기술질의 접수마감)
문의: 한빛조명(주) 영업부
```

## 4. Excel 출력 (FR-21)

파일명: `{bid_no}_대응자료_{YYYYMMDD}.xlsx` (예: `KPG-2025-EQ-0417_대응자료_20250928.xlsx`)

### 4.1 시트 구성 (3개, 순서 고정)

| 시트명 | 내용 |
|---|---|
| `대응표` | 1절 Compliance Matrix + 하단 교차조항 이슈 블록 |
| `제출서류체크리스트` | 2절 제출서류 + 참가자격 + 일정 (세 블록을 빈 행으로 구분) |
| `기술질의서` | 3절 전체 (머리 + 질의 항목 + 꼬리) |

### 4.2 서식

- 1행: 문서 제목 (병합, 14pt bold). 2행: 공고번호·사업명·작성일. 3행: 빈 행. 4행: 헤더.
- 헤더 행: 연회색 배경(`D9D9D9`), bold, 가운데 정렬, 틀 고정(`freeze_panes`).
- 판정 열 셀 배경: 충족 `C6EFCE`, 보완 필요 `FFEB9C`, 확인 필요 `FFC7CE`.
  (Excel 조건부 서식 표준 색상. 색만으로 구분되지 않게 텍스트도 함께 넣는다.)
- 열 너비: 조항 8, 분류 10, 항목 18, 요구조건 28, 자사 사양 18, 판정 12,
  사유 36, 대체방안 36, 근거 문서 28, 근거 위치 20, 비고 24.
- 긴 텍스트 셀은 `wrap_text=True`, 세로 위 정렬.
- 모든 셀에 얇은 테두리.
- `openpyxl` 사용. 수식은 쓰지 않는다 (값만 쓴다).

### 4.3 Markdown 보고서

파일명: `{bid_no}_분석보고서_{YYYYMMDD}.md`

구성:
```
# {사업명} 입찰 기술사양 분석 보고서

## 1. 입찰 개요            (BidProject 필드 표)
## 2. 분석 요약            (판정별 건수 + 실행 메타 + 정확도)
## 3. 기술규격 대응표       (1절)
## 4. 조항 간 상충 사항     (1.3절)
## 5. 제출서류 체크리스트   (2절)
## 6. 기술질의서 초안       (3절)
## 7. 분석 조건            (모델, RAG 파라미터, 프롬프트 버전, 실행 시각)
```

7절을 넣는 이유: 같은 문서를 나중에 다시 봤을 때 어떤 조건으로 나온 결과인지
알 수 있어야 한다. 프롬프트를 바꾸면 결과가 달라지므로 조건 없는 보고서는 재현 불가다.

## 5. 공통 표기 규칙

| 항목 | 규칙 |
|---|---|
| 판정 | `충족` / `보완 필요` / `확인 필요` (영문 enum을 사용자에게 노출하지 않는다) |
| 값 없음 | `-` (빈 문자열 대신) |
| 수치 | 원문 표기 유지. `20,000 lm` 를 `20000lm` 로 바꾸지 않는다 |
| 온도 | `℃` 기호 유지 |
| 근거 문서 | `{문서 제목} ({문서번호})` |
| 근거 위치 | `{절 번호} {절 제목}`, PDF면 `(p.{page_no})` 추가 |
| 날짜 | `YYYY-MM-DD`, 일시는 `YYYY-MM-DD HH:MM` |
| AI 수정 표기 | 사람이 수정한 행은 비고에 `사용자 수정` |

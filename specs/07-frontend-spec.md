# 07. 프론트엔드 명세 (Vue 3 SPA)

Vue 3 + Vite + Bootstrap 5 + Pinia + Vue Router. 데스크톱 1280px 이상 기준.
커스텀 CSS는 최소화하고 Bootstrap 유틸리티 클래스를 쓴다.

## 1. 라우트

| 경로 | 뷰 | FR |
|---|---|---|
| `/` | `BidListView` | FR-22 |
| `/bids/:id` | `BidDetailView` (탭 컨테이너) | FR-22 |
| `/bids/:id/documents` | 탭 1 — 문서 | FR-01, 02, 05 |
| `/bids/:id/requirements` | 탭 2 — 요구사항 | FR-03, 06, 07 |
| `/bids/:id/results` | 탭 3 — 분석 결과 | FR-11, 13~17, 24 |
| `/bids/:id/deliverables` | 탭 4 — 산출물 | FR-18~21 |
| `/knowledge` | `KnowledgeView` | FR-08, 09 |
| `/knowledge/search` | `KnowledgeSearchView` | FR-12 |

상단 네비게이션 2개: `입찰 건` / `지식베이스`. 그 외 메뉴는 만들지 않는다.

## 2. 화면

### 2.1 `BidListView` — 입찰 건 목록

- 카드 또는 테이블 목록: 사업명, 공고번호, 공고기관, 입찰마감, 요구사항 수,
  최근 분석 요약 배지(`충족 7 / 보완 4 / 확인 2`), 정확도(`11/13`).
- `새 입찰 건` 버튼 → 사업명만 입력하는 모달 → 생성 후 문서 탭으로 이동.
- 행 클릭 → 상세. 삭제는 확인 모달 필수.
- 입찰마감이 지난 건은 흐리게 표시한다.

### 2.2 문서 탭 (`DocumentsTab`)

- 드롭존 2개를 나란히 둔다: **입찰공고문** / **기술사양서**.
  종류를 드롭존으로 분리하면 `doc_type` 선택 실수를 줄인다.
- 업로드 후 카드: 파일명, 문서번호, 페이지 수, 표 개수, 상태 배지, 삭제 버튼.
- `추출 결과 보기` → 페이지별 본문과 표를 렌더링하는 모달 (`GET /documents/{id}/pages/`).
  표는 실제 HTML `<table>` 로 그려 사람이 원본과 대조할 수 있게 한다.
- 하단에 입찰 기본정보 카드 (FR-05): 사업명, 공고번호, 품목, 수량, 추정가격, 납품장소,
  납품기한, 일정 3개. 인라인 수정 가능.
- `요구사항 추출` 버튼 → `POST /projects/{id}/extract/`.
  - 기존 요구사항이 있으면 "기존 추출 결과와 수정 내역이 사라집니다" 확인 모달.
  - 완료 후 요구사항 탭으로 자동 이동.
  - `warnings` 는 화면 상단 노란 알림으로 모두 표시한다. 숨기지 않는다.

### 2.3 요구사항 탭 (`RequirementsTab`) — FR-07

분석 전 사람이 반드시 거치는 화면. "추출 → 바로 판정" 자동 진행은 없다.

- 장(chapter)별 그룹 테이블. 열: 조항 / 분류 / 항목 / 요구조건 / 출처 페이지 /
  분석대상 / 채점대상 / 작업.
- 셀 인라인 편집 (`contenteditable` 아닌 클릭→input 전환). 저장은 blur 시 `PATCH`.
- `분류` 는 셀렉트 박스 (FR-06의 12개 값, 한국어 라벨).
- `분석대상` 토글 = `is_active`. 끄면 행이 흐려진다.
- `채점대상` 토글 = `is_graded`. 켜진 개수를 헤더에 표시 (`채점대상 13건`).
- 수정된 행에 `수정됨` 배지.
- `행 추가` 버튼, 행별 `제외`(is_active=false) 버튼. 완전 삭제는 드롭다운 안에 둔다.
- 상단 요약: `총 17건 / 분석대상 17건 / 채점대상 13건`.
- `분석 실행` 버튼 (primary, 큰 버튼).
  - 클릭 시 파라미터 모달: `top_k`, `threshold`, `w_semantic`, `w_keyword`,
    `llm_model`, `교차조항 검증 사용`. 기본값은 `.env` 값을 서버에서 받아 표시.
  - 가중치 2개는 합이 1이 되도록 슬라이더 연동 (하나를 올리면 다른 쪽이 내려간다).
  - 실행 시작 → 결과 탭으로 이동하며 진행률 표시.

### 2.4 결과 탭 (`ResultsTab`) — 핵심 화면

**진행 중**
- 프로그레스 바 + `current_step` 텍스트 (`항목별 판정 (7/17)`).
- `GET /runs/{id}/` 를 2초 간격 폴링. `done`/`failed` 면 멈춘다.
- 탭을 떠나면 폴링을 정리한다 (`onUnmounted`).
- 실패 시 `error_message` 와 `재시도` 버튼.

**완료 후**
1. **요약 바** — 판정별 큰 숫자 + 배지. 클릭하면 해당 판정으로 필터.
   `충족 7` (success) / `보완 필요 4` (warning) / `확인 필요 2` (danger).
   실행 메타(모델, RAG 파라미터, 소요시간, 토큰)를 작은 글씨로 함께 표시.

2. **교차조항 이슈 영역** (있을 때만, 표 위에 배치)
   - `severity=high` 는 빨간 alert, `medium` 은 노란 alert.
   - 제목, 설명(계산 과정 포함), 관련 조항 배지, `무시` 버튼.
   - 항목별 표보다 **위에** 둔다. 이 경고를 못 보고 넘어가면 안 되는 정보다.

3. **대응표 테이블** (`ComplianceTable`)
   - 열: 조항 / 분류 / 항목 / 요구조건 / 자사값 / 판정 / 근거수 / 작업.
   - 판정 배지: 충족(초록) / 보완 필요(노랑) / 확인 필요(빨강).
   - 필터: 판정, 분류, `수정된 항목만`, `채점대상만`.
   - 정렬: 조항번호 기본 (숫자 튜플 정렬 — 문자열 정렬하면 `2.10 < 2.2` 가 된다).
   - 행 클릭 → 아래로 펼침(accordion):
     - `판정 사유`(rationale), `미달 내용`(gap_detail), `대체방안`(remedy)
     - `부작용` 칩 목록 (`무게 +1.4kg`, `납기 +3주`)
     - `검색 쿼리` (디버그용, 작은 회색 글씨)
     - **근거 목록** — `EvidenceCard` 컴포넌트. 문서명·문서번호·위치·페이지·점수
       (결합/의미/키워드)·인용문. 클릭 → `EvidenceModal` 로 부모 청크 전문 표시.
     - `수정` 버튼 → 판정 셀렉트, 자사값, 사유 편집 (FR-17).
       `MEET` 로 바꾸려는데 근거가 0건이면 저장 버튼을 비활성화하고
       "근거가 없는 항목은 충족으로 변경할 수 없습니다" 를 표시한다 (원칙 3을 UI에서도).
   - AI 판정과 현재 판정이 다르면 행에 `수정됨 (AI: 충족)` 배지.

4. **정확도 패널** (`AccuracyPanel`) — FR-24
   - `정확도 측정` 버튼 → `POST /runs/{id}/evaluate/`.
   - 결과: 큰 점수 `11 / 13 (84.6%)`, 판정별 정답 수, 혼동표.
   - 틀린 항목 표: 조항 / 항목 / AI 판정 / 정답 / AI 사유 / 비고.
   - **함정 4개 체크리스트** — 각 함정 이름과 통과 여부(O/X), 실패 시 사유.
     이 패널이 프롬프트 개선의 출발점이다.

### 2.5 산출물 탭 (`DeliverablesTab`)

- `산출물 생성` 버튼 → `POST /runs/{id}/deliverables/`.
- 3개 아코디언 섹션:
  1. **대응표** — 제출 양식 그대로 미리보기 테이블.
  2. **입찰 체크리스트** — 제출서류 8건(체크박스, 상태 배지, 매핑 근거),
     참가자격 3건, 일정(마감 D-day 표시).
  3. **기술질의서 초안** — 질의별 카드. 조항 배지, 문안 textarea(편집 가능),
     `포함` 토글. 편집 시 `PATCH /inquiries/{id}/`.
- 하단 다운로드 버튼 2개: `Excel 다운로드`, `Markdown 보고서`.
  → `POST /runs/{id}/export/` → 응답의 `download_url` 로 이동.

### 2.6 `KnowledgeView` — 지식베이스 관리 (FR-08)

- 상단 경고 배너 (항상 표시):
  > 이 화면에는 **자사 자료만** 올립니다. 입찰공고문과 기술사양서는 입찰 건 화면에서
  > 업로드하세요. 공고·사양서를 지식베이스에 넣으면 다음 입찰 분석의 근거가 오염됩니다.
- 문서 카드 목록: 제목, 문서번호, 종류 배지, 개정일, 상태, 청크 수, 임베딩 모델.
  버튼: `청크 보기`, `재색인`, `삭제`.
- 업로드: 파일(`.pdf`/`.md`), 종류 셀렉트(`제품카탈로그`/`인증·시험·실적`/`기타`), 제목.
  `indexing` 중이면 스피너 + 폴링.
- 서버가 `knowledge_doc_type_forbidden` 을 반환하면 에러 메시지를 그대로 보여준다.
- `청크 보기` 모달: 부모/자식 필터, `section_path`, `chunk_type`, `keywords` 칩,
  `model_tags` 칩, 내용. 부모-자식 계층을 들여쓰기로 표현.

### 2.7 `KnowledgeSearchView` — 검색 테스트 (FR-12)

- 쿼리 입력 + 파라미터 입력(`top_k`, `threshold`, `w_semantic`, `w_keyword`, 모델 필터).
- **예시 쿼리 버튼 3개**: `방수 등급`, `발전소 납품실적`, `염수분무 시험`.
  세 번째 옆에 작은 툴팁: "설비 현황표가 잡히는지 확인 — 함정 4의 전제".
- 결과 목록: 순위, 결합 점수, 의미 점수, 키워드 점수를 각각 프로그레스 바로 표시.
  문서명, 위치, `model_tags`, 내용, `부모 전문 보기` 토글.
- 점수 3개를 나란히 보여주는 것이 이 화면의 존재 이유다. 의미만으로는 `IP65`/`IP66`이
  안 갈리고 키워드가 그것을 가른다는 것을 눈으로 확인할 수 있어야 한다.

## 4. 상태 관리 (Pinia)

| 스토어 | 상태 |
|---|---|
| `bidStore` | 입찰 건 목록, 현재 건 상세, 문서, 요구사항 |
| `analysisStore` | 현재 run, 폴링 타이머, assessments, cross issues, accuracy, deliverables |
| `knowledgeStore` | 지식 문서 목록, 청크, 검색 결과 |
| `uiStore` | 토스트 알림, 전역 로딩, 서버 기본 파라미터 |

폴링 타이머는 `analysisStore` 가 소유하고 `stopPolling()` 을 노출한다.
컴포넌트에서 `setInterval` 을 직접 만들지 않는다 (탭 이동 시 누수의 원인).

## 5. API 레이어

`src/api/` 에만 axios를 쓴다. 컴포넌트에서 `axios` 를 직접 import하지 않는다.

```
src/api/
├── client.js       # axios 인스턴스, baseURL, 인터셉터
├── projects.js     # 입찰 건, 문서, 요구사항
├── knowledge.js    # 지식 문서, 청크, 검색
├── analysis.js     # run, assessment, cross issue, evaluate
└── exports.js      # deliverables, export, download
```

`client.js` 인터셉터: 응답 에러의 `detail` 을 토스트로 띄우고 에러를 재던진다.
`code` 별 특수 처리(예: `run_in_progress` 는 토스트 대신 모달)는 호출부에서 한다.

## 6. UX 원칙

- **판정 결과에 색만 쓰지 않는다.** 배지에 텍스트 라벨(충족/보완 필요/확인 필요)을 항상 넣는다.
- **근거는 언제나 한 번의 클릭 안에 있다.** 판정만 보이고 근거를 찾아 헤매게 만들지 않는다.
- **AI 값과 사람 수정값을 구분해 보여준다.** 무엇이 AI 판정이었는지 추적 가능해야 한다.
- **경고를 접지 않는다.** 추출 경고, 교차조항 이슈는 기본 펼침 상태다.
- 긴 작업(추출, 분석, 산출물 생성)은 버튼을 비활성화하고 스피너를 보여준다. 중복 실행 방지.
- 숫자는 오른쪽 정렬, 조항번호는 등폭 글꼴(`font-monospace`).
- 빈 상태(문서 없음, 요구사항 없음, 분석 없음)마다 다음 행동을 안내하는 문구를 둔다.

## 7. Vite 설정

```js
server: {
  port: 5173,
  proxy: { "/api": { target: "http://localhost:8000", changeOrigin: true } },
}
```
개발 중에는 프록시를 쓰고 `VITE_API_BASE_URL` 은 `/api` 로 둔다.
빌드 배포 구성은 비범위.

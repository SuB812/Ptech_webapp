# 01. 기능 요구사항

각 요구사항은 `FR-xx` ID를 가진다. 커밋·PR·테스트에서 이 ID로 참조한다.
`우선순위`: **P0** = PoC 완료 조건, **P1** = 있으면 데모 품질이 올라감, **P2** = 차기.

---

## A. 문서 분석 (FR-01 ~ FR-05)

### FR-01 입력 문서 업로드 · P0
입찰 건에 PDF를 업로드한다. 문서 종류를 선택한다: `announcement`(입찰공고문) / `techspec`(기술사양서/구매규격서/RFP).

- 허용 확장자: `.pdf` 만. 그 외는 400 에러와 한국어 메시지.
- 최대 크기: 20MB. 최대 페이지: 50p.
- 한 입찰 건에 같은 종류 문서를 여러 개 올릴 수 있다(예: 사양서 + 별첨).
- 업로드 즉시 텍스트·표 추출을 수행하고 결과를 저장한다. 실패 시 `status=failed` 와 사유를 남긴다.

### FR-02 텍스트 및 표 추출 · P0
PDF에서 페이지별 본문 텍스트와 **표를 구조를 유지한 채** 추출한다.

- 표 추출은 `pdfplumber.extract_tables()` 를 사용한다. **필수 사항이다.**
  샘플 `02_기술사양서.pdf` 를 `pdftotext -layout` 으로 추출하면 조항 열과 요구조건 열이
  한 행씩 어긋나 `2.1 소비전력 → 20,000 lm 이상` 같은 오답이 만들어진다.
  이 현상은 `specs/05-rag-pipeline.md` 2절에 기록되어 있다.
- 각 표는 `[[셀,...], ...]` 2차원 배열 + 페이지 번호로 저장한다.
- 표 밖의 서술 문장(예: "설치 장소는 해안에서 약 2km", "미달 시 대체방안을 명시")도
  보존한다. 판정 맥락에 쓰인다.

### FR-03 요구사항 자동 추출 · P0
추출된 텍스트·표에서 요구사항을 조항 단위 배열로 뽑는다.

출력 필드: `clause_no`(조항번호), `category`(분류), `item`(항목), `requirement_text`(요구조건),
`source_page`(출처 페이지), `order`(표시 순서).

- 사양서의 장 구조(제2장 성능 / 제3장 구조 / 제4장 시험 / 제5장 품질보증)를 `category` 로 매핑한다.
- 샘플 기준 **17개 조항**(2.1~2.5, 3.1~3.4, 4.1~4.4, 5.1~5.4)이 모두 추출되어야 한다.
- 조항번호가 없는 서술형 요구(예: 공고문 3.3 참가자격 "발전소 납품실적 3건 이상")도
  추출하고 `clause_no` 에 출처 표기(`공고 3.3`)를 넣는다.
- LLM 출력은 JSON 스키마로 검증한다. 파싱 실패 시 1회 재시도, 그래도 실패하면 에러 반환.

### FR-04 제출서류 목록 추출 · P0
입찰공고문의 제출서류 표를 추출해 체크리스트로 만든다.

- 샘플 기준 8건(입찰참가신청서 ~ 공인시험기관 시험성적서)이 연번·서류명·비고와 함께 나와야 한다.
- 각 서류에 자사 보유 상태를 매핑한다: `보유` / `발급 필요` / `확인 필요`.
  매핑 근거는 지식베이스 검색으로 찾는다(예: KS 인증서 → 인증현황 1절 `KSC-2022-1180`).

### FR-05 입찰 기본정보 추출 · P1
공고 개요 표에서 사업명, 공고기관, 공고번호, 구매품목, 수량, 추정가격, 납품장소, 납품기한,
그리고 일정 표에서 기술질의 접수마감·입찰서 제출마감을 추출해 입찰 건 헤더에 표시한다.

## B. 요구사항 분류 (FR-06 ~ FR-07)

### FR-06 요구사항 분류 체계 · P0
각 요구사항을 다음 `category` 중 하나로 분류한다.

| 값 | 표기 | 예 |
|---|---|---|
| `dimension` | 제품 치수 | 외형 크기, 본체 무게 |
| `filter_grade` | 등급 | 방수·방진 등급(IP66), 필터 등급 |
| `efficiency` | 효율 | 광효율 140lm/W, 소비전력 150W |
| `pressure_drop` | 차압 | (본 샘플에는 없음. 필터류 품목 대비 필드 유지) |
| `test_standard` | 시험규격 | 내염수분무 240시간, KS C 7658, 내진동 |
| `certification` | 인증 | KS 인증, 고효율에너지기자재 인증 |
| `delivery` | 납기 | 계약 후 60일, 보증기간 3년 |
| `submission` | 제출서류 | 시험성적서, 대응표, 납품실적증명서 |
| `performance` | 성능 | 총 광속, 색온도, 수명 |
| `material` | 재질·구조 | 알루미늄 다이캐스팅, 표면처리 |
| `track_record` | 실적 | 발전소 납품실적 3건 이상 |
| `other` | 기타 | 위에 없는 것 |

분류는 LLM이 하되 위 목록 외 값을 내면 `other` 로 강제한다.

### FR-07 요구사항 검토·수정 · P0
자동 추출 결과를 사용자가 화면에서 확인하고 수정한다.

- 조항번호/항목/요구조건/분류 인라인 편집, 행 추가, 행 삭제.
- 삭제 대신 `is_active=false` 로 제외 처리(추출 원본 보존).
- 채점 대상 여부 토글(`is_graded`) — 정확도 측정 대상 13개를 지정하기 위함.
- 분석 실행 전에 이 화면을 반드시 거친다. "추출 → 바로 판정" 자동 진행은 하지 않는다.

## C. 기술자료 비교 (RAG) (FR-08 ~ FR-12)

### FR-08 지식 문서 업로드 · P0
자사 기술자료를 업로드해 RAG 지식베이스에 색인한다.

- 허용 형식: `.pdf`, `.md`. (샘플 자사 자료는 `.md`)
- `doc_kind`: `catalog`(제품카탈로그) / `qa`(인증·시험·실적) / `other`.
- 업로드 후 청킹 → 임베딩 → 저장까지 수행하고 진행 상태를 표시한다.
- 재색인 버튼: 청킹 파라미터를 바꾼 뒤 기존 문서를 다시 색인한다.
- **공고문·사양서는 이 화면에서 업로드할 수 없다.** UI와 서버 양쪽에서 막는다.

### FR-09 부모-자식 청킹 · P0
자식 청크로 검색하고, LLM에는 부모 청크(표 전체)를 전달한다.

- 표는 잘라내지 않는다. 표 한 개 = 부모 청크 1개.
- 자세한 규칙은 `specs/05-rag-pipeline.md` 3절.

### FR-10 하이브리드 검색 · P0
의미 검색(pgvector 코사인) + 키워드 검색(pg_trgm / full-text)을 가중 결합한다.

- 기본값: 의미 0.6 / 키워드 0.4, `top_k=5`, `score_threshold=0.4`.
- 값은 `.env` 로 조정 가능하고, 분석 실행 시 사용한 값을 `AnalysisRun` 에 기록한다.

### FR-11 항목별 반복 검색 · P0
활성 요구사항 개수만큼 반복하며 **항목 하나당 검색 한 번**을 수행한다.

- 검색 쿼리 = `item` + `requirement_text` 를 조합해 생성 (`specs/06-analysis-pipeline.md` 3절).
- 요구사항을 묶어 한 번에 검색하는 구현은 금지.
- 각 요구사항별 검색 결과(청크 ID, 점수)를 저장해 재현 가능하게 한다.

### FR-12 지식베이스 검색 테스트 · P1
쿼리를 직접 입력해 검색 결과와 점수를 확인하는 디버그 화면.

- 기본 제공 예시 쿼리 3개: `방수 등급`, `발전소 납품실적`, `염수분무 시험`.
  (세 번째가 청킹 품질을 드러낸다 — 설비 현황표가 잡히는지 확인용)
- 의미/키워드 각각의 점수와 결합 점수를 나란히 표시한다.

## D. 판정 및 결과 표시 (FR-13 ~ FR-17)

### FR-13 대조 판정 · P0
요구사항 1건 + 검색된 근거를 LLM에 주고 판정을 받는다.

출력: `verdict`(MEET/GAP/CHECK), `our_value`(자사값), `rationale`(판정 사유),
`gap_detail`(미달 내용), `confidence`(0~1), `evidences`(근거 목록).

- `verdict` 는 3값 외 불허. 위반 시 `CHECK` 로 강제하고 경고 로그.
- **근거 0건이면 `MEET` 저장 금지** (서버 검증). `CHECK` 로 강제한다.
- 자사 자료에 "미보유"라고 **명시**된 경우도 `CHECK` 다. 단 `rationale` 에
  "설비 현황에 미보유 명시"처럼 근거를 붙여 "검색 실패"와 구분한다
  (→ `evidence_state`: `found_insufficient` / `found_absent` / `not_found`).

### FR-14 근거 표시 · P0
판정 행을 펼치면 근거를 본다.

- 문서명, 문서번호, 절/표 위치, 페이지, 인용 문장, 검색 점수.
- 근거 클릭 → 부모 청크 전문을 모달로 표시.
- 근거가 2건 이상이면 모두 나열한다(점수 내림차순).

### FR-15 결과 화면 · P0
대응표를 표로 표시한다.

- 열: 조항 / 분류 / 항목 / 요구조건 / 자사값 / 판정 / 근거 / 비고.
- 판정별 색상 배지: 충족(초록) / 보완 필요(노랑) / 확인 필요(빨강).
- 판정·분류로 필터, 조항번호 정렬.
- 상단 요약: 충족 n / 보완 필요 n / 확인 필요 n, 총 n건.

### FR-16 교차조항 검증 · P0
항목별 판정이 끝난 뒤 조항 간 상충을 별도로 검사한다.

- 대상: 선택사양·대체방안으로 해결하는 `GAP` 항목.
  그 선택사양의 부작용(무게/단가/납기 증가)을 다른 요구사항과 재대조한다.
- 샘플 필수 검출: 조항 3.1(IP66 선택사양 → 무게 +1.4kg) vs 조항 3.2(8kg 이하)
  → 7.2 + 1.4 = 8.6kg > 8kg 상충.
- 검출된 이슈는 별도 영역에 경고로 표시하고 기술질의서 후보로 넘긴다.
- 상세 알고리즘: `specs/06-analysis-pipeline.md` 5절.

### FR-17 판정 수정 · P0
사용자가 판정과 자사값, 사유를 수정한다.

- 수정하면 `is_edited=true`, `edited_at` 기록, AI 원본값(`ai_verdict` 등)은 보존.
- 화면에 "수정됨" 표시. 정확도 측정은 AI 원본값으로 한다(사람 수정을 정답으로 세면 측정이 무의미).

## E. 대응자료 생성 (FR-18 ~ FR-21)

### FR-18 Compliance Matrix 생성 · P0
판정 결과를 제출용 대응표로 만든다. 양식: `specs/10-output-templates.md` 1절.

- 공고문 5.2("규격 미달 항목은 사유와 대체방안을 대응표에 기재")를 반영해
  `GAP` 항목에는 사유와 대체방안 열을 채운다.

### FR-19 입찰 체크리스트 생성 · P0
제출서류 목록(FR-04) + 참가자격 + 일정을 하나의 체크리스트로 만든다.
양식: `specs/10-output-templates.md` 2절.

### FR-20 기술질의서 초안 생성 · P0
질의 후보를 모아 발주처 회신 요청 문안을 만든다.

후보 규칙:
1. 모든 `CHECK` 항목
2. 대체방안 승인이 필요한 `GAP` 항목
3. 모든 교차조항 이슈(FR-16)

- 조항번호를 명시한 정중한 공문체 한국어. 예시는 `specs/10-output-templates.md` 3절.
- 사용자가 문안을 편집하고 개별 질의를 제외할 수 있다.

### FR-21 다운로드 · P0
- Excel(.xlsx): 시트 3개 — `대응표`, `제출서류체크리스트`, `기술질의서`.
- Markdown 보고서(.md): 요약 + 3개 산출물 전체.
- 파일명: `{공고번호}_{산출물}_{YYYYMMDD}.xlsx`

## F. 결과 관리 (FR-22 ~ FR-24)

### FR-22 입찰 건 관리 · P0
입찰 건 목록/생성/조회/삭제. 목록에 사업명, 공고번호, 최근 분석일, 판정 요약을 표시한다.

### FR-23 분석 실행 이력 · P1
한 입찰 건에 여러 번 분석을 실행할 수 있다.

- 실행별로 모델명, 프롬프트 버전, RAG 파라미터, 소요시간, 판정 요약, 정확도를 기록.
- 실행 목록에서 과거 결과를 조회한다. (실행 간 diff 비교는 비범위)

### FR-24 정확도 측정 · P0
정답표와 대조해 정확도를 계산한다.

- 채점 대상 13개 항목(`is_graded=true`)에 대해 `ai_verdict` vs 정답 비교.
- 출력: 정확도 `n/13`, 판정별 혼동표, 틀린 항목 목록(AI 판정 / 정답 / AI 사유).
- 함정 4개 각각의 통과 여부를 별도 표시.
- 기준: `specs/09-acceptance-tests.md`
